# 全体の仕組み

更新日: 2026-10-13  
対象: プロジェクトのappフォルダー

## 5つの担当

| 区分 | 何をするか | ファイル数 |
| --- | --- | --- |
| フロントエンド・画面 | ボタン、時間割、時刻入力などを表示する | 6 |
| フロントエンド・状態管理 | 入力や選択を覚え、操作を処理へ渡す | 5 |
| バックエンド・設定管理 | 選択枠、授業時刻、表示モードなどを保存する | 1 |
| バックエンド・処理 | 曜日・時刻を判断し、通知変更や予約を行う | 5 |
| バックエンド・受信処理 | 予約時刻や端末再起動の知らせを受け取る | 1 |

起動の準備は、共通のApplicationSetup.ktにまとめています。本体は合計19ファイルです。

## 操作するときの流れ

例えば、時間割の「月曜日・1限」を選ぶと次のように動きます。

1. 画面が、押された枠を状態管理へ伝えます。
2. 状態管理が、処理へ選択を依頼します。
3. 処理が選択の保存と、許可がある場合の開始・終了時刻の予約を行います。
4. 画面が、選んだ枠を色付きで表示します。

予約時刻になると、受信処理がAndroidからの知らせを受け取り、処理へ渡します。処理が一時停止中か確認し、通知を切り替えます。

## 具体的なファイルのつながり

| 操作 | 関係するファイル |
| --- | --- |
| 時間割の枠を押す | TimetableEditorPage → TimetableState → TimetableScheduling → AppSettings・AlarmScheduling |
| 授業時刻を保存する | LessonTimeEditorPage → LessonTimeEditorState → LessonTimeSettings → TimetableScheduling |
| 予約時刻になる | AlarmReceivers → NotificationAutomation → NotificationControl・AlarmScheduling |

表の名前にはそれぞれ.ktが付きます。画面を表示するコードと、端末を操作するコードの担当を分けています。

## ファイルの読み分け

| 知りたいこと | 読む部分 |
| --- | --- |
| 画面がどう表示されるか | 名前がPage.ktで終わる画面ファイル |
| 入力や選択をどう覚えるか | 状態管理のファイル |
| 何を保存しているか | AppSettings.kt |
| 曜日・時刻・通知・予約のルール | 処理の5ファイル |
| 時刻や再起動の知らせをどう受け取るか | AlarmReceivers.kt |

画面は表示と操作の受付を担当し、通知や予約は処理側が担当します。関連する内容は同じファイルにまとめています。
